# SDK recorder conformance

These cases test the **SDK half** of the recorder protocol
([SPEC.md §10](../../../SPEC.md#10-recorder-protocol), §10.6): that an SDK,
recording the conformance handler (§9.6), writes exactly the expected frames
into the recorder pipe. Every SDK runs all of them.

The SDK is started with [`fake_recorder.py`](fake_recorder.py) as its recorder
command instead of `kavach-recorder`. The fake answers like the recorder would
(`ready`, scripted `snapshot_request`s, `durable`, `closed`), and when the
stream closes it compares every frame it received with the case and writes a
verdict file. It needs Python 3.10+ and nothing else.

An SDK that offers the shared-memory ring (SPEC.md §10.7) runs every case over
the pipe and again over the ring, and passes both. When the `open` frame has
`ring`, the fake maps file descriptor 3, or the file named by `ring_path`
(which it unlinks) when there is one, checks the header, reads every later
frame from the ring as §10.7 describes (it polls, treats a byte on standard
input as a doorbell, and on end of standard input drains the ring up to
`write`), and compares the frames the same way. The frames a case lists are
the same for both transports, except that the `open` frame also has `ring` and
perhaps `ring_path`, which the cases do not list.

## What an SDK's runner does, per case

1. Read the case file (`<name>.json`).
2. Create the SDK's recorder for the conformance handler, with:
   - `service`, `start` and `snapshots` from the case's `open`;
   - recorder command `python3 <path>/fake_recorder.py <case.json> <result.json>`.
     **Every SDK must accept a recorder command as an option** (an argument
     vector), besides `KAVACH_RECORDER`;
   - a clock, random source, gateway connection (any gateway name) and config
     provider that serve each step's `answers`, in order, per kind:
     `clock` values are Unix nanoseconds as strings; `rand` values are base64
     and have exactly the length requested; `gateway` answers are
     `{"response": <base64>}` or `{"error": <string>}` (the query fails with
     that error); `config` answers are `{"value": <base64>}` or
     `{"unset": true}`, and the source may be any string;
   - a flag provider that reports the case's `flags` (values are UTF-8), if any;
   - the conformance handler, restored from `snapshot` (decimal ASCII) if the
     case has one.
3. Perform `actions` in order:
   - `{"step": {...}, "answers": {...}}`: record one step whose input has the
     given `source`, `position`, and exactly the bytes of base64 `data`. (`ops`
     is the same thing decoded, for reading.) A step that fails is not an
     error for the runner.
   - `{"flush": {"durable": true}}`: ask the SDK to flush, durably, and wait
     until the recorder answers `durable`. This is also how a case makes sure
     the SDK has seen any control message the fake sent before it.
4. Close the recorder, waiting for `closed`.
5. The case passes if `result.json` has `"pass": true`. On failure, its
   `error` names the first frame that differed, and `frames` holds everything
   received.

## Expected frames

`frames` lists every frame in order, decoded:

| Frame | Decoded as |
| --- | --- |
| `open` | `{"frame": "open", "open": {...}}`. Only the keys listed are compared; the SDK may send others. |
| `record` | `{"frame": "record", "type": ..., "critical": bool, ...fields}`, fields as in `spec/testdata/valid/*.json`: bytes base64, `unix_nanos` as a string, `scope` as `"remote"`/`"local"`, `present` as a boolean. |
| `step_end`, `close` | `{"frame": "step_end"}`, `{"frame": "close"}` |
| `facts` | `{"frame": "facts", "facts": {key: {"value": b64} \| {"sha256": b64} \| {"unset": true}}}`. Keys must match exactly, except that extra `host.x.` keys are allowed. |
| `snapshot` | `{"frame": "snapshot", "data": b64}` |
| `flush` | `{"frame": "flush", "durable": bool}` |

The string `"*"` matches any value. Cases use it for `host.runtime`, a
marker's `data` (a stack trace) and a config record's `source`.

## Changing cases

Cases are generated by [`gen.py`](gen.py): edit them there and run
`python3 spec/recorder/sdk/gen.py`; never edit the `.json` files by hand. A new
case is a change to the contract every SDK must meet.
